## 操作中发现的问题

### P1：测试数据结果覆盖并伪装成最新候选结果

运行 dry-run 后，`candidate_pipeline_latest` 被测试报告替换，训练页原先带真实 Run ID 的候选表被测试数字替换。主表直接展示“当前选择”、年化超额和留出期结果，却没有在表头、每行和结论旁醒目标明“内置测试数据、不可用于研究或交易”。

这会让用户把模拟数字误认为新训练结果，也会暂时失去原先真实候选结果的默认入口。dry-run 应写入独立命名空间，不得发布成正式 `latest`，更不能进入正式“可回测”列表。

### P1：页面把不可回测的 dry-run 结果列为“可回测”

训练页为 dry-run 结果生成“回测”链接。跳转后虽然模型和策略注入成功，但 Run ID 显示为 `-`，“运行回测”按钮不可点击，页面也没有解释测试训练不保存真实预测、因此无法重新回测。

应从“可回测”列表排除缺少 Run ID 或预测产物的结果，或者改成“查看模拟结果”，并明确说明不能执行真实回测。

### P2：前后端版本不一致时，训练按钮无解释地变灰

首次进入页面时，新前端请求 `/api/v1/quant/job-types`，但 7 月 30 日启动的旧后端尚未提供该接口并返回 404。页面保留旧状态，两个“运行”按钮均为禁用状态，同时不显示加载失败、版本不一致、重试或重启提示。

本轮重启 DSA 后端后恢复。页面应把任务目录加载失败显示为明确错误；健康接口还应暴露前后端构建版本，发现不一致时直接提示重启。

### P2：正式训练前置条件缺失

服务重启后，页面明确提示：最新完整数据质量报告缺失或无效，因此正式 LightGBM 基线和正式五模型流程被锁定。这个拦截本身正确，但训练页只能跳转数据页，不能在当前上下文中启动所需报告并在完成后自动回到训练。

2026-08-02 已完全通过网页依次发布 canonical V2、cleaned V2 并运行完整质量报告 `qj_20260802022714_74428906`。页面刷新后显示“当前数据可训练”，不可变报告确认两套 provider 均为 `benchmark_complete=true`、`trainable=true`。正式训练仍未执行，下一步可以开始正式 UI 训练验收。

### P2：任务卡与右侧日志状态不同步

canonical V2 任务 `qj_20260802021325_664e9196` 和 cleaned V2 任务 `qj_20260802021649_35c83b02` 已完成时，任务卡会更新为“完成”，但右侧日志区域仍可能停在“运行中”以及较早的 `read 3000/5508` 进度。只有手动刷新页面后，顶部运行中任务数和训练准备状态才可靠更新。

这不影响后台产物，但会让人误判任务仍在运行或卡死。任务完成事件应同时刷新任务卡、日志尾部、顶部运行计数和数据准备状态；日志被截断时也应明确显示“仅展示部分日志”。

### P2：网页没有暂停和恢复

运行中只提供“取消”，没有“完成当前子任务后暂停”“恢复同一配置”“显示检查点”和“确认恢复时数据/代码哈希一致”。后台鲁棒研究脚本已经支持协作式暂停和恢复，网页尚未接入。

### P2：严格鲁棒训练流程没有网页入口

网页训练页目前只有单个 LightGBM 基线和旧五模型候选流程。Goal 1 鲁棒信号研究、滚动鲁棒开发、确认期和持久化 launcher 都无法由人类用户在网页中配置、启动或恢复。

### P3：复选框交互容易被重渲染打断

勾选“小样本预演”时，控件状态实际上已变为 checked，但自动化交互等待了 3 秒后仍报告超时。重新读取页面后才能确认操作成功。这说明轮询刷新可能在交互期间重渲染控件；人工点击未必每次失败，但应增加前端稳定性测试。

### P3：进度信息过少

任务卡只有“运行中/完成”，没有五个模型当前进行到第几个、百分比、已用时间、预计剩余时间和当前产物。详细阶段只能打开文本日志查看。

### 运维问题：残留无监听旧进程

本机同时残留一个运行近四天但未监听 8010 的旧 DSA 进程，容易让维护者误判服务已经启动。本轮已清理，并把当前服务放入持久化 `screen` 会话 `dsa-8010`。

## 网页与后台脚本能力差距

| 能力 | 后台脚本 | 当前网页 |
| --- | --- | --- |
| 单模型基线 | 支持 config、experiment、provider | 支持 |
| 固定不可变 provider 快照 | `--provider-uri` | 不可选择或查看具体快照 ID |
| 不覆盖 latest | `--no-publish-latest` | 不支持 |
| 独立结构化结果文件 | `--result-output` | 不支持 |
| 五模型候选 spec | `--spec` | 不支持 |
| 小样本预演 | `--dry-run` | 支持，但结果隔离错误 |
| 鲁棒信号 smoke | `--smoke`、指定季度和信号 | 无入口 |
| 协作式暂停 | `--request-pause` | 无入口 |
| 断点恢复 | `--resume` | 无入口 |
| 指定 run ID | `--run-id` | 无入口 |
| 关闭 MLflow | `--no-mlflow` | 无入口 |
| 鲁棒开发计划预览 | `--plan-only` | 无入口 |
| 指定 as-of 日期 | `--as-of-date` | 无入口 |
| launchd 持久化和 warm-up | launcher 支持 | 页面任务由后端运行，但不显示 runner、PID、利用率或 warm-up 结果 |
| 训练后回测注入 | 需要手工传产物 | 网页可自动选择模型和交易策略，但 dry-run 被错误当成可回测结果 |
| 数据质量门槛 | 直接运行脚本可绕过；API 有守卫 | 网页会阻止正式训练，安全性更好 |

`--provider-identity-json`、输出目录和内部时间戳属于后端受控参数，不建议直接开放为自由文本；网页应展示其最终值，但继续由服务端生成和校验。
