# BVR 成交反馈修订

BVR 的阈值、39只证券池、T+1开盘、仓位上限、最多加仓次数均未调整。
修订脚本为 `quant_workflow/scripts/bvr20_fill_feedback.py`；原已保存脚本和旧回测仍按各自 SHA 保留。

旧脚本先计算整段信号，再交由撮合器处理整手、现金和停牌，导致发出加仓目标时已修改买入价及次数，实际未成交也会被计数。
修订脚本定义可选 `on_fill(context, trade)`，在原 macOS 沙箱内与现有撮合器按时间顺序执行：先执行当日开盘订单，再反馈真实成交，最后产生当日收盘信号。

- 只有正数量的实际买入产生买入反馈；未成交、停牌、整手不足不更新加仓次数和买入价。
- 首次真实买入建立入场价和模式；后续对应加仓信号的真实买入才增加计数并更新成交价。部分卖出保留入场状态，全部卖出后清除。
- 无法得到有效B触碰价格时返回None，不把布尔值当价格。False→None的修复保留。
- 回调中的 `trade`、`context.positions` 为只读副本；`context.cash` 为成交后现金。启用反馈的脚本在收盘时看到真实持仓权重，不将请求目标冒充已成交持仓。
- 显式再次提交相同目标时重新按实际持股计算；保留最后一日不可执行信号、停牌重试和T+1限制。
- 明确提交的现金或持仓目标会覆盖旧待执行目标，即使它与当前实际持仓相同；没有新指令时仍保留原停牌重试。
- 省略可选开始日期时，反馈执行与重放均从所选输入的首日计价，包括首次成交前的现金日；不删去净值点来规避一致性校验。
- 普通脚本的既有信号路径不变；仅定义 `on_fill` 的脚本启用反馈。单独调用信号生成接口执行此类脚本会明确拒绝，应使用 `run_script_backtest_in_sandbox` 或正常回测服务。

主回测、比较策略和稳定性窗口复用同一反馈信号。父进程使用既有撮合器复核成交和净值一致，再附加比较结果，未新增服务、数据库或外部连接。
本修订不调整费率，不实现原研究的完整券商成交约束，也不自动修改任何行情或历史运行。

## 仅放宽短暂停牌数据不足的候选

以78f1d8e为行为基线：B入场准备检查最近25个市场交易日，21～24条有效收盘可继续计算，少于21条返回None。每个触碰检查窗口仍必须有20个实际收盘，不缩短BOLL周期；只在现有25日数据内计算，不额外向前取行情。

原20日价格/量窗口不完整时，仅为B入场准备从这批有效收盘取最近20条计算中轨与上轨。原触碰公式、触碰价格返回类型、days_left=3观察逻辑、买卖确认、退出和均量、仓位、指数及成交反馈均原样保留。特别是确认阶段仍调用原_bands()；不会为了让新观察成交而连带放宽确认或退出。

25条数据齐全时保持78f1d8e行为，包括原成交量不足时不建立观察的边界。不会增加触碰后5日确认截止、market_bar、touch_bar或新的计时状态；ba9e417中相关改动已撤回。

候选只改仓库代码，不更新正式策略资产。正式版本、旧脚本和已有回测继续保留；对照回测使用相同冻结数据、参数和撮合器。
