# A 股鲁棒量化策略项目计划

更新日期：2026-07-19

适用项目：`daily_stock_analysis/quant_workflow`

## 1. 最终目标

本项目要得到的不是单独一个“选股模型”，也不是单独一套“买卖规则”，而是一套完整、可复现的 A 股量化策略：

1. 量化选股：每天收盘后，根据当时已经知道的数据，给历史时点 CSI800 股票排序。
2. 组合构建：从排序结果中选出持仓，并限制单股、行业、创业板和科创板仓位。
3. 交易执行：按周调仓，使用下一交易日开盘价模拟成交，并处理停牌和涨跌停。
4. 成本核算：计入佣金、最低佣金、印花税和滑点。
5. 风险控制：根据市场状态降低仓位，限制回撤和集中度。
6. 严格验证：通过多训练窗口、多随机种子、滚动样本外、牛熊环境、板块归因、成本压力、执行延迟、2026 确认期和 60 个交易日纸面跟踪。

只有选股和交易两部分一起通过全部门槛，策略才能叫“鲁棒策略合格”。历史回测通过但尚未完成前向跟踪时，只能叫“研究候选”。

## 2. 不可降低的边界

- 使用历史时点 CSI800 成分股，不能拿今天的成分股回看过去。
- 训练和选择只能使用 2025 年及以前的开发期数据。
- 2026 年确认期只能运行一次，不能根据 2026 结果重新挑模型或调参数。
- 任何失败都必须如实输出失败原因，不能降低门槛后宣布成功。
- 只做多，不融资、不做空、不连接券商、不自动下单。
- 行情、模型、预测、MLflow Runs 和训练产物不进入 Git。
- 正式运行必须绑定 Git 提交、配置哈希和数据清单哈希。

## 3. 选股模型与交易策略的关系

选股模型回答的是：**未来一周，哪些股票相对更可能表现较好？**

交易策略回答的是：**根据这个排序，实际买哪些、买多少、什么时候换、遇到风险怎么减仓、扣除成本后是否仍然有效？**

因此，量化交易包含选股，但不等于选股。模型预测正确，也可能因为换手过高、成本过大、持仓过度集中或无法成交而亏损。

## 4. 模型候选计划

### 4.1 当前正在运行的传统模型候选

当前正式开发 Run 使用五类模型：

| 模型 | 作用 | 主要目的 |
| --- | --- | --- |
| OLS | 线性基线 | 检查简单、稳定关系是否已经足够 |
| Ridge | 带正则的线性模型 | 降低因子共线和过拟合 |
| LightGBM | 梯度提升树 | 学习非线性和因子交互 |
| XGBoost | 另一类梯度提升树 | 检查树模型结果是否依赖单一实现 |
| CatBoost | 另一类提升树 | 增加模型结构和训练机制的多样性 |

这五类模型是第一轮稳健基线，不代表“所有值得研究的模型”。此前没有把神经网络纳入第一轮，是为了先把历史股票池、时间切分、交易成本和验收门槛做正确，并控制一次正式运行的计算规模。这是范围选择，不是已经证明神经网络无效。此前没有提前把这个取舍说清楚，项目计划在此纠正。

当前统一训练条件：

- 训练窗口：504、756、1008 个交易日。
- 树模型随机种子：42、2026、3407。
- 开发期：2023Q1 至 2025Q4，共 12 个滚动样本外季度。
- 每个测试季度之前保留约 126 个交易日验证期。
- 目标：T 日收盘生成信号，预测 T+1 开盘到 T+6 开盘的 5 日收益。
- 固定参数先跑；未通过稳定性门槛的模型最多执行 20 组有界调参。

### 4.2 正式纳入的 MPS 神经网络候选线

本轮新增要求是：鲁棒策略的候选模型不能只有线性模型和树模型，必须有至少一个经过同等验收的神经网络候选。这个要求已经写入正式训练协议，但不能反向修改已经启动的 Run。

因此分两步执行：

1. 当前 `robust_20260719_development_v2` 继续按原来的五类传统模型完成。它是已冻结的阶段性证据，不会因为新增 DNN 而中途改配置。
2. `mps_dnn_v1` 已在隔离分支接入正式编排器。当前 Run 结束并审计后，先合并和复核这批实现，再创建一个**统一六模型 Run**：OLS、Ridge、LightGBM、XGBoost、CatBoost 和 MPS DNN 必须在同一 Git 提交、同一配置哈希、同一 provider 状态、同一数据清单哈希和同一开发期切分下重新运行。不能把当前五模型 Run 与另一个 DNN Run 的指标直接拼成一个“最终组合”。

这意味着 MPS DNN 不是事后可有可无的附加实验，而是下一轮正式选模的六个候选之一；当前独立分支只是为统一 Run 准备并验证实现。

第一步只加入 MLP/DNN，原因是 Alpha158 当前是表格型价量因子，MLP/DNN 可以直接在相同输入和相同时间切分下与线性模型、树模型公平比较。LSTM、GRU、Transformer、ALSTM、GAT 和 TCN 需要另外构造时序张量、掩码和批处理逻辑，不应在同一轮未经验证地全部铺开。这不是永久排除这些网络，而是先用一个能公平比较、能严格复现的神经网络基线；只有它完成后续启动条件，才增加时序网络。

MPS DNN 必须满足：

- 使用 Apple GPU 的 MPS 后端；设备不可用时直接失败，禁止静默回退 CPU。
- 使用可复现的独立 Python 环境和锁定依赖，不改当前正式 Run 的环境。
- 使用同一份历史时点 CSI800、同一 Alpha158 输入、同一标签、同一季度切分和同一验收门槛。
- 使用 504、756、1008 三种窗口和 42、2026、3407 三个随机种子；DNN 也必须使用这三个种子，不能只挑一次运行结果。
- 记录每次训练的设备、依赖版本、随机种子、模型结构、模型哈希和 MLflow Run ID。
- 把不含本机路径的 Python、Qlib、树模型库、PyTorch 版本和 MPS 可用状态写入开发上下文并计算环境哈希；运行结束时重新核对，环境变化则整轮失败。
- 增加重复训练一致性检查，防止 MPS 非确定性造成结果漂移。
- 比较 DNN 与传统模型的预测排名相关性；只有带来独立且稳定的有效信号时，才有资格进入集成。
- 不查看 2026 确认期来选择网络层数、宽度、学习率或早停参数。

神经网络不会因为“更复杂”而自动获得优先权。它必须通过相同门槛，才能与传统模型一起进入最终 2 至 3 个模型的等权百分位排名集成。未通过时，报告“神经网络候选未通过”，不能为了保留神经网络而降低标准。

### 4.3 后续时序神经网络的启动条件

LSTM、GRU 或 Transformer 不在当前立即执行范围内。满足以下条件后，才单独立项：

1. MLP/DNN 已证明训练、恢复、MPS 设备锁定和结果复现链路可靠；并且
2. 开发期证据表明时序结构可能补充现有模型，而不是只增加计算量；或
3. MLP/DNN 与传统模型高度相关，但仍有明确、可检验的时序信息缺口。

旧 `quant_workflow` 中的 LSTM 实验只能作为代码参考。它使用旧 provider、当前成分股和固定切分，没有满足本项目的历史时点 CSI800、成本和验收协议，不能直接计入本项目结果。

## 5. 数据计划

数据范围从 2014-01-02 开始，覆盖 2015 牛熊转换、2018 下跌、2020 冲击和后续市场。

正式数据必须包含：

- 历史时点 CSI300、CSI500 和合并后的 CSI800 成员区间。
- A 股日线开高低收、成交量和成交额。
- SH000300、SH000905、SH000906 三个基准。
- 上市和退市日期、行业区间、ST 区间、停牌状态和板块标识。

训练前数据门槛：

- 历史成员覆盖率不低于 99%。
- 有效 OHLCV 覆盖率不低于 98%。
- 无重复日期、未来数据和基准缺口。
- 元数据缺失或股票状态自相矛盾时，状态必须是 `blocked_data`，不得启动训练。

`quant_data` 只保存正式数据产品和运行缓存；目录、数据来源、哈希和生成命令必须由清单记录，不能靠 Agent 猜测。

## 6. 牛熊市和板块处理

第一版不分别训练牛市模型和熊市模型。统一模型生成股票排名，市场状态只控制下一交易日的股票总仓位：

- `risk_on`：90%
- `neutral`：70%
- `defensive`：50%
- `risk_off`：20%

只有某一市场状态连续两个样本外区间失效，且该状态累计不少于 252 个交易日，才启动专用模型实验。

主板、创业板和科创板第一版统一训练，但进行板块内标准化和仓位约束：

- 单股不超过 3%。
- 单一行业不超过 25%。
- 创业板与科创板合计不超过 30%。

报告必须分别展示牛熊状态、主板、创业板、科创板和行业归因，不能只展示总收益。

## 7. 交易策略候选

所有合格选股模型使用同一交易模拟器比较五套规则：

1. 周频 Top50：作为交易基线，不参与最终冠军选择。
2. 低换手：检查减少换仓能否保留信号并降低成本。
3. 市场状态减仓：根据信号日已经知道的市场状态调整总仓位。
4. 行业与板块约束：限制集中度。
5. 完整组合风控：包含周频调仓、低换手、状态仓位、行业和板块限制，是唯一可成为最终策略的规则。

回测必须处理停牌、涨跌停、板块涨跌幅制度变化、下一开盘无法成交和最低佣金。另做 10、20、40 个基点总成本和延迟一个交易日执行测试。

## 8. 开发期验收门槛

开发期必须全部满足：

- 12 个季度中至少 70% 取得扣费后正超额收益。
- 汇总年化超额收益不低于 5%。
- 季度信息比率中位数不低于 0.5。
- 至少 70% 的样本外区间 RankIC 为正。
- 不同训练窗口预测排名相关性中位数不低于 0.70。
- Top50 平均重合率不低于 60%。
- 最差样本外最大回撤不超过 20%。
- 40 基点成本下汇总超额收益仍为正。
- 延迟一个交易日执行后汇总超额收益仍为正。
- 四种市场状态中至少三种取得正超额。
- 样本不少于 60 日的市场状态，年化超额不得低于 -5%。

至少 2 个、至多 3 个模型通过模型稳定性门槛后，才能构建等权百分位排名集成。传统模型和神经网络使用同一资格标准。若六模型统一 Run 中 DNN 未通过，它会被记录为“神经网络候选未通过”，不得为了保留 DNN 降低门槛；若统一 Run 发生前视、上下文不一致或产物来源无法核对，则整轮结果无效，不能选择其中看起来最好的模型。

## 9. 2026 确认期和 60 日纸面跟踪

开发期选定模型和完整交易规则后，必须冻结：

- Git 提交
- 配置哈希
- 数据清单哈希
- 模型和参数
- 组合与交易规则

冻结后只运行一次 2026 确认期。要求：

- 净超额收益大于 0。
- 信息比率大于 0。
- 最大回撤不超过 20%。

确认期通过后进入 60 个交易日纸面跟踪。要求：

- 累计净超额收益大于 0。
- 最大回撤不超过 12%。
- 每日任务成功率不低于 95%。

未完成 60 个交易日前向跟踪前，状态只能是 `shadow_observation`，不能叫“鲁棒策略合格”。

## 10. 状态定义

| 状态 | 通俗含义 |
| --- | --- |
| `blocked_data` | 数据不完整，训练不能开始 |
| `development_failed` | 数据合格，但模型或交易策略没有通过开发期门槛 |
| `research_candidate_ready` | 开发期通过，配置已冻结，尚未完成确认和前向跟踪 |
| `shadow_observation` | 2026 确认通过，正在进行 60 日纸面跟踪 |
| `robust_strategy_qualified` | 全部门槛和 60 日跟踪均通过 |

运行中的临时状态是 `status=running` 且 `lifecycle_status=running`，它不代表任何验收门槛已经通过。只有进程停止后，才会写入上表中的最终状态。

## 12. 接下来按什么顺序执行

1. 让当前五模型 Run 完整结束，不中途改配置或挑选局部最好结果。
2. 审计所有固定参数和调参结果；不足 2 个模型通过时，如实记录当前 Run 的结果，不能把它包装成最终策略。
3. 审查并合并隔离分支中已经完成的 `mps_dnn_v1` 编排、MLflow 归属、运行环境指纹和失败持久化实现；合并后重新运行完整鲁棒测试。
4. 在一个新的 Git 提交上创建统一六模型 Run，完整运行 OLS、Ridge、LightGBM、XGBoost、CatBoost 和 MPS DNN；统一记录 `git_commit`、`config_hash`、`development_context_hash`、`provider_key` 和每个模型产物哈希。
5. 仅用 2023Q1 至 2025Q4 选择 2 至 3 个合格且不过度相关的模型；不得从两个不同上下文的 Run 拼接候选集合。
6. 对统一 Run 的模型集成运行五套交易策略和全部成本、延迟、牛熊、板块测试。
7. 开发期全部通过后冻结代码、配置、数据和模型，再运行一次 2026 确认期。
8. 确认期通过后开始 60 个交易日纸面跟踪。
9. 只有全部完成后，才能把 Goal 标记为完成。
